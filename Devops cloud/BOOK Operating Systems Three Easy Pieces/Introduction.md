Each process accesses its own private virtual address space
(sometimes just called its address space), which the OS somehow maps
onto the physical memory of the machine. A memory reference within
one running program does not affect the address space of other processes
(or the OS itself); as far as the running program is concerned, it has phys-
ical memory all to itself. The reality, however, is that physical memory is
a shared resource, managed by the operating system. Exactly how all of

is an operating system mechanism that gives each process its own isolated virtual address space. Each process uses virtual addresses that are translated into physical memory addresses by the Memory Management Unit (MMU), using page tables managed by the operating system. The MMU also enforces memory access permissions, such as read, write, and execute. This allows multiple processes to use the same virtual addresses while accessing different physical memory locations. Memory virtualization provides process isolation, protection, and efficient management of shared physical RAM.

Design Goals : ^EFxWbbEd

The main design goals of an Operating System (OS) are Abstraction, Performance, Protection, and Reliability. Abstraction hides hardware complexity and provides simple interfaces such as processes, virtual memory, and files. Performance aims to minimize time and space overhead while efficiently managing system resources. Protection ensures isolation between processes and between user applications and the kernel through mechanisms such as memory protection, privilege separation, and access controls. Reliability ensures that the operating system remains stable and handles failures appropriately. Additional goals include security, energy efficiency, and mobility. OS design requires trade-offs, because improving one property may increase the cost or reduce the performance of another. A good operating system balances these goals according to its intended workload and requirements. ^90gSAcSZ

Early Operating Systems primarily provided libraries of reusable functions, such as low-level I/O routines, and commonly used Batch Processing, where jobs were collected and executed without continuous user interaction. As operating systems evolved, Protection and Isolation became essential because applications needed controlled access to hardware and system resources. Modern operating systems use CPU privilege levels, mainly User Mode (restricted execution) and Kernel Mode (privileged execution). Applications request protected OS services through System Calls, which trigger a controlled transition into Kernel Mode using hardware-supported instructions. The kernel validates the request, performs the operation, and returns control to User Mode. Unlike a normal Procedure Call, a System Call involves a privilege transition and typically introduces additional overhead. A Mode Switch changes the CPU privilege level, while a Context Switch changes the running thread or process; the two are not equivalent. ^k26lAq2M
